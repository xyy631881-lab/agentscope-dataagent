# AgentScope 2.0 升级指南

本文档记录 data-agent 项目从 AgentScope v1 风格到 v2.0 内置能力的升级过程，
以及各优化项的说明与配置示例。

> 升级日期: 2026-06-29 | 版本: 2.0.0-SNAPSHOT

---

## 已完成的优化

### 1. ChatController SSE 事件流简化

**Before**: 3 个 `ConcurrentHashMap` 分别跟踪 `toolNames`、`toolInputs`、`toolResults`，
在事件流中手动累积 tool delta 后合成 SSE 事件。

**After**: 使用单个 `Map<String, ToolBuffer>` 统一管理工具调用状态，
`ToolBuffer` 内部类封装 `toolName` + `input` + `result` 三个字段，
代码量减少约 30%，逻辑更清晰。

```java
// 关键改动: ChatController.java
private static final class ToolBuffer {
    final String toolName;
    final StringBuilder input = new StringBuilder();
    final StringBuilder result = new StringBuilder();
}

// 3 maps → 1 map
final Map<String, ToolBuffer> buffers = new ConcurrentHashMap<>();
```

### 2. 消息构造 API 现代化

**Before**: `Msg.builder().role(MsgRole.USER).textContent(msg).build()`

**After**: 使用 v2.0 子类构造器，角色固定，类型更安全。

| 文件 | 旧写法 | 新写法 |
|------|--------|--------|
| ChatController.java | `Msg.builder().role(USER)...` | `new UserMessage("user", msg)` |
| AgentDraftService.java | `Msg.builder().role(USER).content(TextBlock)...` | `new UserMessage(TextBlock)` |
| OutboundService.java | `Msg.builder().role(ASSISTANT).name("outbound")...` | `new AssistantMessage("outbound", text)` |
| AnnounceDispatcher.java | `Msg.builder().role(USER).name("subagent_announce")...` | `new UserMessage("subagent_announce", text)` |
| WebhookInboundMapper.java | `Msg.builder().role(USER).name(userId)...` | `new UserMessage(userId, msg)` |

### 3. 记忆压缩 (Compaction)

**Before**: 依赖手写的 `SessionFreshness` / `SessionResetPolicy` 管理会话生命周期。

**After**: 启用 v2.0 内置 compaction，自动处理对话上下文窗口溢出。

```java
// DataAgentConfig.java
b.compaction(CompactionConfig.builder()
    .triggerMessages(30)   // 累积 30 条消息时触发压缩
    .keepMessages(10)      // 压缩后保留最近 10 条 + 摘要
    .build());

b.memory(MemoryConfig.builder()
    .flushTrigger(MemoryConfig.FlushTrigger.throttled(Duration.ofMinutes(10)))
    .build());
```

**效果**:
- Agent 自动获得 `memory_search` 和 `memory_get` 工具，可主动检索历史
- 对话要点自动合并到 `MEMORY.md` + `memory/YYYY-MM-DD.md`
- 压缩过程对 Agent 透明，不中断正常对话

> **注意**: 当前与手写的 `SessionStore` / `SessionFreshnessEvaluator` 共存，
> 后续可在充分验证后移除自定义 session 管理代码。

### 4. Plan Mode

**Before**: 无任务规划能力。

**After**: 一行配置启用 Plan Mode。

```java
// DataAgentConfig.java
b.enablePlanMode();
```

**效果**:
- Agent 获得 `plan_enter` / `plan_write` / `plan_exit` 三个工具
- 规划阶段只读（不能执行副作用工具）
- 规划完成后需用户确认才进入执行阶段
- 规划文件持久化到 `plans/PLAN.md`

**适用场景**:
- 多表关联 SQL 分析（先确认 schema → 规划查询 → 执行）
- 统计报告生成（确认指标 → 规划章节 → 逐一生成）
- 复杂数据分析流水线

### 5. 模型容错

```java
// DataAgentConfig.java
b.maxRetries(2);    // 主模型调用失败时自动重试 2 次
```

后续可添加 fallback:

```java
// 当 DashScope 不可用时回退到 OpenAI
b.fallbackModel("openai:gpt-4.1-mini");
```

### 6. 内置子代理声明 ✅ (Phase 3 完成)

**Before**: 完全依赖手写的 `SessionsTool` + `SessionAgentManager` 进行子代理管理。

**After (Phase 2)**: 添加 v2.0 内置子代理声明，与现有 `SessionsTool` 共存。

**After (Phase 3)**: `SessionsTool` 已从 `DataAgentBootstrap` 中完全移除。子代理现在由
AgentScope 2.0 内置的 `SubagentsMiddleware` 全权管理。Agent 使用标准工具
`agent_spawn` / `agent_send` / `agent_list` / `agent_kill` / `task_list` / `task_output`。

```java
// DataAgentConfig.java — Phase 3 最终配置
// SubagentDeclaration 替代了 sessions_spawn 的手工实现
b.subagent(SubagentDeclaration.builder()
    .name("code-reviewer")
    .description("Code review specialist...")
    .model("dashscope:qwen-max")
    .maxIters(5)
    .exposeToUser(false)
    .workspaceMode(WorkspaceMode.SANDBOX)
    .build());

b.subagent(SubagentDeclaration.builder()
    .name("report-writer")
    .description("Report writer...")
    .model("dashscope:qwen-max")
    .maxIters(8)
    .exposeToUser(true)    // 用户可见子代理思考过程 (#10)
    .workspaceMode(WorkspaceMode.SANDBOX)
    .build());
```

**子代理也可用 Markdown 文件声明**（推荐方式）:

```markdown
<!-- workspace/subagents/code-reviewer.md -->
---
description: Code review specialist.
model: dashscope:qwen-max
max_iters: 5
expose_to_user: false
---

You are a code reviewer...
```

**v2.0 内置 vs SessionsTool 对比**:

| 能力 | SessionsTool (自研) | v2.0 内置 |
|------|-------------------|-----------|
| 声明方式 | 代码 + JSON 配置 | Markdown 或 SubagentDeclaration |
| 同步/后台 | 支持 (timeout_seconds) | 支持 (timeout_seconds + task_id) |
| 后台通知 | 需手动处理 | 自动推送 |
| 流式事件转发 | 不支持 | **自动转发** (带 source 路径) |
| expose_to_user | 不支持 | 支持 |
| Plan Mode 继承 | 不支持 | 自动继承 |

### 7. 权限系统

```java
// DataAgentConfig.java
PermissionContextState permCtx = PermissionContextState.builder()
    .addAllowRule(new PermissionRule("list_data_sources", null, ALLOW, "default"))
    .addAskRule(new PermissionRule("run_sql_preview", null, ASK, "sql_execution"))
    // ... 其他规则
    .build();
b.permissionContext(permCtx);
```

**规则优先级**: DENY → ASK → 工具自检 → ALLOW

**当前配置**:
- SQL 执行 (`run_sql_preview`) 需用户确认 (ASK)
- 其他工具默认放行 (ALLOW)

### 8. 子代理流式事件自动转发 (通过 #6 获得)

v2.0 内置子代理的事件流自动带 `source` 字段（例如 `"main/report-writer"`），
前端可根据此字段展示"子代理 report-writer 正在思考..."等 UI 效果。

### 9. ToolNotificationMiddleware 标记为可迁移

已添加 `TODO` 注释: 当 ChatController 的统一 SSE 流覆盖所有 tool 事件后，
`ToolNotificationMiddleware` + `ToolEventBus` 可整体移除。

## 配置一览

所有 v2.0 优化在 `DataAgentConfig.builderBootstrap()` 的
`configureAllAgents` 回调中集中配置：

```java
builder.configureAllAgents(b -> {
    // ---- 平台基础设施 ----
    b.middleware(new ToolNotificationMiddleware(toolEventBus));
    b.stateStore(stateStore);
    b.filesystem(new DockerFilesystemSpec()...);

    // ---- #6 模型容错 ----
    b.maxRetries(2);
    // b.fallbackModel("openai:gpt-4.1-mini");  // 需要时取消注释

    // ---- #5 Plan Mode ----
    b.enablePlanMode();

    // ---- #3 记忆压缩 ----
    b.compaction(CompactionConfig.builder()
            .triggerMessages(30).keepMessages(10).build());
    b.memory(MemoryConfig.builder()
            .flushTrigger(MemoryConfig.FlushTrigger.throttled(Duration.ofMinutes(10)))
            .build());

    // ---- #2 子代理声明 ----
    b.subagent(/* code-reviewer */);
    b.subagent(/* report-writer */);

    // ---- #9 权限系统 ----
    b.permissionContext(/* allow 'list_data_sources', ask 'run_sql_preview' */);
});
```
