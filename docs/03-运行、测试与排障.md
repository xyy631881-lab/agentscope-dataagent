# 运行、测试与排障

## 1. 本地依赖

| 依赖 | 默认位置 | 用途 |
|---|---|---|
| JDK | Java 17+ | 编译和运行 Spring Boot |
| Maven | 3.9+ | 后端构建与测试 |
| Node.js | 20+ 推荐 | 前端构建 |
| MySQL | `localhost:3306` | 用户、Agent、会话、审批、用量、Trace、分析数据 |
| Redis | `localhost:6379` | 启用 redis profile 时保存运行态、快照和 guard |
| Docker Desktop | 本机 Docker Engine | 文件工具/Sandbox |
| 模型服务 | LongCat、OpenAI 兼容服务或 Ollama | 模型推理 |

配置文件位于 `src/main/resources/application*.yml`。不要把生产 API Key 直接提交到 `application.yml`。

## 2. 常用命令

在项目根目录执行。

```powershell
# 后端全部单元测试
mvn test

# 单独构建前端，并把产物写到 Spring Boot 静态目录
Set-Location frontend
npm.cmd run build

# 回到项目根目录，启动默认 8080
Set-Location ..
mvn spring-boot:run

# 打包前后端（需要 Node/npm）
mvn -Pfrontend package -DskipTests

# 健康检查
Invoke-WebRequest -UseBasicParsing http://localhost:8080/actuator/health
```

当前前端 `vite build` 的输出目录是 `src/main/resources/static/`。修改前端后，只重启 Java 进程而不重新执行 `npm.cmd run build`，页面仍会加载旧 bundle。

## 3. 最小验证清单

1. 启动后访问 `/actuator/health`，应返回 HTTP 200。
2. 登录并进入 `/chat`，新建一次对话，确认 SSE 能返回文本或工具轨迹。
3. 打开 `/usage`，普通用户看到个人数据；管理员可在同页切换平台/个人范围。
4. 打开 `/traces`，完成一条消息后应能看到对应运行记录。
5. 使用两个用户创建同名私有 Agent，分别进入技能页，确认路径和技能互不影响。
6. 在技能页卸载 `chart-rendering`，刷新页面或重新进入后确认不自动出现。

## 5. 已踩坑与解决办法

### 5.1 私有 Agent 同名工作区串数据

**现象**：不同用户都使用 `personal-agent` 时，技能、子 Agent 或定义文件可能互相可见；页面/API 与聊天运行时还可能读取不同目录。

**根因**：旧实现把私有定义路径直接按 `workspacePath` 解析，默认值相同；控制面修了但运行时仍可能使用旧路径。

**修复**：统一调用 `WorkspaceManagerFactory.userWorkspacePath(userId, agentId)`，路径固定为 `.agentscope/users/{userId}/agents/{agentId}`；`AgentMutationService`、`WorkspaceResolutionService`、`AgentLifecycleService` 均使用该方法。

**验证**：两个用户创建同 ID 私有 Agent，比较 `userWorkspacePath`；运行和技能页均应落在各自目录。

### 5.2 删除 Skill 后又出现在列表中

**现象**：卸载 `chart-rendering` 成功后，刷新或重新进入技能页又出现。

**根因**：历史私有 Agent 每次列举时都会补齐团队基础 Skill；此外 GET 允许浏览器缓存，删除后的列表可能读到旧响应。

**修复**：首次基础 Skill 初始化写 `.dataagent/public-skills-v1` 标记；已有 Skill 的历史 Agent 不再补齐缺失项。技能列表和详情请求使用 `cache: 'no-store'`；DELETE 成功后前端先移除状态，再请求服务端二次确认。

**注意**：不要手动删除旧 `.agentscope/personal-agent-workspace`，其中可能仍有历史数据。

### 5.3 Windows Docker Desktop 下 `/workspace` 路径异常

**现象**：Docker Sandbox 报工作区创建失败或容器内找不到 `/workspace`。

**根因**：Windows 的 Java `Path` 可能把 Linux 容器路径转换为反斜杠，`docker exec` 里的 shell 再把反斜杠当转义，最终创建了错误路径。

**修复**：`RetryStartDockerSandbox` 在启动前后用 `docker exec ... mkdir -p /workspace` 硬编码 POSIX 路径，并在容器瞬时退出时做有限重试和状态探测。

### 5.4 `tar: file changed as we read it`

**现象**：会话结束附近归档 workspace 时，刚写入文件导致 tar 读取过程检测到变化。

**修复**：只对该可恢复的并发归档错误短暂重试，最多 3 次、间隔 250ms；其他 Sandbox 异常仍然抛出，避免掩盖真实故障。

### 5.5 本地镜像导致工作区页面长时间转圈

**现象**：产物已存在，但页面读取时先尝试恢复失效 containerId，等待很久才失败。

**修复思路**：读取优先使用宿主机只读镜像，镜像不存在时再访问 Sandbox；写、移动、删除仍走 Sandbox。这样改善可用性但不改变运行时事实来源。

### 5.6 运行审计阻塞首个 SSE 事件

**现象**：冷启动/冷恢复时，首个流式事件迟迟不出现。

**根因**：把 `RUN_SESSION` 审计写入放在开流同步路径，会与 Agent 对同一个隔离槽竞争。

**修复原则**：把非关键审计延后到流结束处理，并让其可观测、可降级；会话数据库记录才是权威事实。

### 5.7 Ollama `ThinkingBlock` 警告

**日志**：`OllamaChatFormatter - Unsupported block type ThinkingBlock ... skipped`。

**解释**：所用 Ollama formatter 不识别框架消息中的 ThinkingBlock，于是跳过它。该警告通常不等于聊天失败，但会丢弃不能被目标模型协议承载的思考块。

**处理建议**：确认所选模型/formatter 对应关系；升级支持该块的适配器，或在进入 Ollama formatter 前过滤不支持的块。不要把内部思考文本当业务审计内容保存。

### 5.8 浏览器报 `Unexpected token '<' ... is not valid JSON`

**含义**：前端按 JSON 解析响应，实际拿到了 HTML，常见是 404 被 SPA fallback 返回 `index.html`、反向代理改写路径、运行旧静态 bundle 或接口前缀不一致。

**排查顺序**：

1. 在浏览器 Network 查看请求 URL、状态码、响应 `Content-Type` 与响应正文。
2. 直接访问对应后端 API，确认它返回 JSON 而不是 HTML。
3. 确认 Java 进程已加载最新 `src/main/resources/static/` 构建产物。
4. 检查反向代理是否把 `/api/**` 错误重写到前端入口。

### 5.9 长页面无法滚动、底部内容被裁掉

**根因**：`AppShell` 是固定视口，过去主内容容器 `overflow: hidden`；没有自带滚动容器的用量、资料、偏好等页面超出首屏后不可达。

**修复**：工作台主内容层改为 `overflow: auto` 且加入 `minHeight: 0`；运行记录内容区设置 `flex: 1`、`minHeight: 0`、`overflow: auto`。聊天、工作区编辑器等已有内部滚动的页面不改其滚动归属。

### 5.10 管理台与用户端功能重复

**问题**：个人用量和管理员用量曾是两套页面，字段和图表漂移；用户端功能混在管理菜单也增加认知成本。

**修复**：`/usage` 统一承载个人/平台数据，管理员切换范围；`/admin/usage` 兼容跳转，管理侧栏移除重复入口。平台数据仍受后端管理员鉴权保护。

## 6. 当前已知边界

| 边界 | 当前状态 | 后续建议 |
|---|---|---|
| MySQL + 文件系统 + Redis 一致性 | 无分布式事务 | staging、Outbox、补偿任务和对账 |
| Skill 回滚 | 版本归档可用 | 使用 manifest 计算差集，清理旧版本新增残留文件 |
| Skill 安全 | 有路径校验 | 增加 Prompt Injection、危险命令、远程资源和敏感文件扫描 |
| SQL 安全 | 应用限制 + HITL | 使用只读数据库账号、AST 校验、超时与审计 |
| 多实例 | Redis 适配已具备 | 做两个实例的并发、故障转移和 lock lease 验证 |
| 评测 | 尚未形成统一离线集 | 建立工具选择、SQL 正确率、任务完成率和回归集 |
